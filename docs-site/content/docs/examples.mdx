These examples use public data or a session imported from your own browser. None of
them writes to leroymerlin.es.

## find a store

```bash
leroymerlin store list --query valencia --format pretty
```

```bash
leroymerlin store list --compact --format jsonl | jq -r .slug
```

The slug is the stable key. Store names change; the slug in `/tiendas/<slug>.html`
does not.

## browse the category tree

Start at the top level and narrow down one step at a time:

```bash
leroymerlin category list --depth 1 --format pretty
leroymerlin category list --parent construccion --depth 2 --format pretty
leroymerlin category list --query cemento
```

Accents are ignored in `--query`, so `almeria` finds `Almería`.

## find a material

```bash
leroymerlin search "cemento cola" --format pretty
leroymerlin search "mortero" --brand SIKA --max-price 30 --sort price-asc
leroymerlin search --category construccion/cementos-morteros-y-yesos/cementos --in-stock
```

The site renders the first eighteen results and lazy-loads the rest card by card.
`search` reports the total and the pages the site states, and the products the
page embedded. `--limit` trims the page you asked for.

## check one product

```bash
leroymerlin product show 81866477 --format pretty
leroymerlin product stock 81866477
```

`product stock` says which store the session has selected, whether the product is
online, and the delivery options the page lists. With a selected store it adds a
pickup row per store (`on order`, `in stock` or `out of stock`, free when the price
is 0). Without one it reports online availability only; see
[the session notes](/docs/reference/login).

## get a browser session

Choose a store on leroymerlin.es first. Stock follows the store selected in the
browser session.

The easy way copies your real Chrome profile's cookie store into a temporary directory,
opens Chrome on the copy and reads the session out of it, user agent included:

```bash
leroymerlin auth harvest
leroymerlin auth status --check
```

Chrome 136+ does not open a DevTools port on its default profile, so the copy is what
makes the port work, and the trusted `datadome` cookie travels with it. The copy is
`0700` and is always removed with the browser. It attaches to a Chrome already listening
on a DevTools port when there is one, and falls back to a fresh profile (which may need a
hand-cleared check) when no real profile exists.

A session you already have as a file can be imported. A HAR from DevTools carries the
browser's user agent:

```bash
leroymerlin auth login --cookies ~/Downloads/leroymerlin-cookies.json
leroymerlin auth login --har ~/Downloads/leroymerlin.har
```

## one profile per store

A profile is one imported session. Use one profile per store to compare stock without
re-importing cookies.

```bash
leroymerlin auth login --cookies madrid.json --profile madrid
leroymerlin auth login --cookies getafe.json --profile getafe
leroymerlin profile use madrid
leroymerlin doctor --profile getafe
```

## read the config

```bash
leroymerlin config path
leroymerlin config list
leroymerlin config set default_profile madrid
```

The config file is plain TOML. Sessions are not stored there.

## pipe the output

```bash
leroymerlin category list --format jsonl | jq -r 'select(.depth == 1) | .name'
leroymerlin store list --format json | jq -r '.[].url'
```

Use `--no-input` in scripts and agents. It stops the cli from waiting on a prompt when
something is missing; the command fails with exit `2` instead.
