## `leroymerlin auth`

Import, inspect or forget the browser session

Import, inspect or forget the browser session the cli replays.

leroymerlin.es sits behind bot protection that answers scripts with a
challenge page. The cli gets through by replaying your own browser's cookies
(and its user agent) over a Chrome-like TLS handshake. No password is ever
asked for, and an account is not needed: a guest session with a store
selected is enough.

### `leroymerlin auth harvest`

Read the session out of a real Chrome window

```bash
leroymerlin auth harvest [flags]
```

Open leroymerlin.es in a real Chrome and read the session it earns, instead
of exporting cookies by hand.

The browser opens headed so you can clear any DataDome check it shows; the
window stays open while the command waits. If a Chrome debug endpoint is
already running (--browser-url, LEROYMERLIN_CHROME_URL, or the default
http://localhost:9222), the command attaches to it instead of launching.

By default it copies the cookie store of your real Chrome profile into a
temporary directory, launches Chrome on that copy and reads the trusted session
from it. Chrome 136+ ignores --remote-debugging-port on the default profile, so
the copy is what makes the DevTools port work. The copy, and the browser that
used it, are deleted on every path out. --profile picks the Chrome profile
directory (not the session profile: use LEROYMERLIN_PROFILE or default_profile
for that). Without a real profile it launches a fresh one, which may need a
human to clear a check.

The harvested cookies and the browser's own user agent are stored 0600 exactly
as `auth login` stores an export. Choose your store in that window
before harvesting: stock follows it.

```bash
leroymerlin auth harvest
leroymerlin auth harvest --profile ~/.config/google-chrome
leroymerlin auth harvest --chrome /usr/bin/chromium --timeout 2m
leroymerlin auth harvest --browser-url http://127.0.0.1:9222
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--browser-url` | string | - | attach to this Chrome DevTools endpoint instead of launching (env LEROYMERLIN_CHROME_URL; default: probe http://127.0.0.1:9222) |
| `--chrome` | string | - | Chrome or Chromium binary (env LEROYMERLIN_CHROME) |
| `--profile` | string | - | Chrome profile directory to copy (env LEROYMERLIN_CHROME_PROFILE; default: auto-detect). Not the session profile: use LEROYMERLIN_PROFILE for that |
| `--timeout` | duration | `5m0s` | how long to wait for the challenge to clear |
| `--user-agent` | string | - | override the user agent (default: the browser's own) |

### `leroymerlin auth login`

Import leroymerlin.es cookies or a HAR from your browser

```bash
leroymerlin auth login [flags]
```

Import leroymerlin.es cookies or a HAR exported from your browser.

1. Open leroymerlin.es in Chrome and choose your store ("Elegir mi tienda").
   Logging in is not needed.
2. Export the cookies with a cookie-export extension (JSON or cookies.txt),
   or save a HAR from DevTools > Network with "Allow to generate HAR with
   sensitive data" enabled.
3. Pass the file here.

Accepted: cookie JSON (array or \{"url","cookies"\} wrapper), DevTools cookie
lists, Netscape cookies.txt, a Cookie: header, HAR 1.2. Only leroymerlin.es
cookies are kept, so a whole-browser export is fine. A HAR also carries your
browser's user agent, which the cli then sends.

The session is stored 0600 under the config directory. For CI, point
LEROYMERLIN_COOKIEJAR at an export instead: it is read on each run and never
written to disk.

```bash
leroymerlin auth login --cookies ~/Downloads/leroymerlin-cookies.json
leroymerlin auth login --har ~/Downloads/leroymerlin.har --profile valencia
pbpaste | leroymerlin auth login --cookies-stdin --cookies-format header
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--cookies` | string | - | cookie export file (JSON, cookies.txt or a Cookie: header) |
| `--cookies-format` | string | `auto` | auto, json, netscape, header or har |
| `--cookies-stdin` | bool | - | read the export from stdin |
| `--har` | string | - | HAR file saved from DevTools with sensitive data included |
| `--no-check` | bool | - | save without asking the storefront whether the session works |
| `--user-agent` | string | - | user agent of the browser the cookies came from (a HAR provides it) |

### `leroymerlin auth logout`

Forget the stored session of this profile

```bash
leroymerlin auth logout
```

Delete the stored session of this profile. Your browser session is not touched.

### `leroymerlin auth status`

Show the session in use (cookie names only, never values)

```bash
leroymerlin auth status [flags]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| `--check` | bool | - | also ask the storefront whether the session works (one request) |
